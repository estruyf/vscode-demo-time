The EngageTime actions allow you to control the behavior of the EngageTime integration during your presentation. You can use these actions to start/close an EngageTime session or poll for responses.

## What is EngageTime?

[EngageTime](https://engagetime.live) is a audience engagement service that lets presenters run live polls, Q&A, and sessions that attendees can join with a session code. Demo Time integrates with EngageTime so you can start or control sessions directly from your demo scripts.

## Prerequisites

To use the EngageTime actions, you need to have an EngageTime account and API key. 

1. Go to [engagetime.live](https://engagetime.live) and sign up for an account if you don't have one.
2. Obtain your API key from the [API Management](https://engagetime.live/speaker/api-keys) section in your account settings.
3. Execute the `Demo Time: Settings` command in VS Code.
4. Open the **EngageTime** section, enter the key in the **EngageTime API key** field and save the settings.

## Available actions

The following EngageTime actions are available:

- `startEngageTimeSession` — Start an EngageTime session.
- `closeEngageTimeSession` — Close an active EngageTime session. 
- `showEngageTimeSession` — Show the session link and QR.
- `startEngageTimePoll` — Start a poll within an EngageTime session. Requires `pollId`.
- `closeEngageTimePoll` — Close a running poll. Requires `pollId`.
- `showEngageTimePoll` — Show poll results. Requires `pollId`.
- `sendEngageTimeMessage` — Send a message to the EngageTime session timeline. Requires `type`, and `title`.

All these actions require you to define the `sessionId` of the EngageTime session you want to control. You define the `sessionId` at the root of your act file:

You can set the `sessionId` in the demo configuration under the `Act file Settings` section:

You can set the `sessionId` at the root of your act file:

```yaml
title: EngageTime
description: Test out the EngageTime interaction
version: 3
engageTime:
  sessionId: 4fn3gy
scenes:
  - id: demo-mevoasl4-rp3l
    title: Start a session
    moves:
      - action: startEngageTimeSession
```

## Poll actions

The following actions control polls inside an EngageTime session. All poll actions require the `pollId`. When the session ID has been defined, the poll can be easily selected from the dropdown in the action UI. If you are using the code approach, you can retrieve it from the URL.

### Start a poll

Start a poll that has been configured in your EngageTime session using `startEngageTimePoll`.

<Tabs syncKey="start-engagetime-poll">
<TabItem label="JSON">

```json
{
  "action": "startEngageTimePoll",
  "pollId": "poll-1"
}
```

</TabItem>
<TabItem label="YAML">

```yaml
action: startEngageTimePoll
pollId: poll-1
```

</TabItem>
</Tabs>

### Show poll results or UI

Use `showEngageTimePoll` to display the poll. By default, the poll opens in the Visual Studio Code integrated browser. Set `pollInPreview` to `true` to show it in the Demo Time preview instead, the same view that shows your slides. You can set **either** `startOnOpen` to start the poll when shown, **or** `closeOnOpen` to close it immediately when shown (for quizzes or timed questions). These options are mutually exclusive.

The poll embed supports two additional appearance options:

- `pollDarkTheme` — When `true`, opens the poll embed with the dark theme (`?theme=dark`). Defaults to the light theme.
- `pollControls` — Controls whether the poll UI controls are shown in the embed. Defaults to `true`.

Where the poll is shown:

- `pollInPreview` — When `true`, shows the poll in the Demo Time preview instead of the integrated browser. Defaults to `false`.

<Aside type="caution">
**Integrated browser (default):** the browser keeps the keyboard focus and doesn't pass the arrow and page keys to Visual Studio Code. Your next and previous keys, or clicker, only work again after you close the browser tab or click outside of it.

**Demo Time preview (`pollInPreview: true`):** the keyboard focus stays in Visual Studio Code, so your next and previous keys, or clicker, keep moving through the scenes while the poll is on screen, and the next slide replaces the poll. The limitation is that links in the poll, like the session link in the **Join the session** dialog, can't be opened, and the text of the poll can't be selected or copied.
</Aside>

<Tabs syncKey="show-engagetime-poll">
<TabItem label="JSON">

```json
{
  "action": "showEngageTimePoll",
  "pollId": "poll-1",
  "startOnOpen": false,
  "closeOnOpen": true,
  "pollDarkTheme": true,
  "pollControls": false,
  "pollInPreview": true
}
```

</TabItem>
<TabItem label="YAML">

```yaml
action: showEngageTimePoll
pollId: poll-1
startOnOpen: false
closeOnOpen: true
pollDarkTheme: true
pollControls: false
pollInPreview: true
```

</TabItem>
</Tabs>
