Demo Time is more than just a tool for live demos, it also lets you present slides seamlessly within your editor. With Markdown-based slides, you can deliver presentations without switching between different applications, ensuring a smooth transition between your slides and demos.

<Image class="mx-auto" src={slidesImg} alt="Slides in Demo Time" />

## Creating slides

To create slides, start by creating a new Markdown file and adding your content:

```md
---
theme: default
---

# Title

Hello, **Demo Time**!
```

Slides support all the markdown you know, like lists, tables, images and [code blocks](/slides/code-blocks/) with syntax highlighting. Code blocks can highlight lines step by step, animate the changes between versions of your code, and show the code of a file in your workspace.

You can also create multiple slides within the same Markdown file by separating them with three hyphens (`---`). This is useful for grouping related slides together. For example:

```md
---
theme: default
---

# Slide 1 Title

Content for the first slide.

---

# Slide 2 Title

Content for the second slide.
```

To give a slide its own front matter, put it directly after the `---` separator and close it with another `---`:

```md
# Slide 1 Title

---
layout: section
---

# Slide 2 Title
```

The block is only used as front matter when it is valid YAML with `key: value` properties. Otherwise, the `---` is a plain separator, so a slide can start with a line like `Note: remember this`. A `---` inside a code block (fenced with ` ``` ` or `~~~`) does not start a new slide.

### Front matter for all slides

The front matter at the top of the file is the document front matter. It belongs to the first slide, and the other slides in the file inherit from it:

- `theme` and `customTheme` apply to every slide. When the document front matter sets them, a slide can't use another value.
- `transition`, `header`, `footer`, `background` and `class` apply to every slide that doesn't set its own value.
- Any other property, like the properties you use in a [custom layout](/slides/layouts/custom/), applies to every slide that doesn't set its own value.
- `layout`, `customLayout`, `image`, `autoAdvanceAfter` and `hide` only apply to the first slide.

The [front matter reference](/slides/front-matter/) shows this for every property.

```md
---
theme: frost
transition: fadeIn
---

# Slide 1 Title

---
transition: slideLeft
---

# Slide 2 Title
```

Both slides use the `frost` theme. The first slide uses the `fadeIn` transition, the second slide its own `slideLeft` transition.

<Aside type="tip">
To make the process easier, you can use the `Demo Time: Create a slide` command. This command will start the slide creation process where you will be asked for a title and if you want to add it to any of your demos.
</Aside>

## Slide settings

You can customize your slides using the following properties in the front matter:

- `theme` - Specify the theme for the slide.
- `layout` - Choose a layout for the slide.
- `transition` - Set the transition effect for the slide.
- `image` - Set a background image for the slide.
- `background` - Set a colour, gradient or image as the background of the slide. See [slide background and classes](#slide-background-and-classes).
- `class` - Add CSS classes to the slide, so a custom theme can style it. See [slide background and classes](#slide-background-and-classes).
- `video` - Set a video for the slide (works with video layout or custom layouts).
- `customTheme` - Provide a custom CSS file for the slide.
- `customLayout` - Specify a custom layout for the slide.
- `autoAdvanceAfter` - Automatically advance to the next slide or demo after a specified number of seconds.
- `hide` - Skip the slide while presenting. See [hiding slides](#hiding-slides).
- `autoFit` - Scale the content down when it doesn't fit on the slide. See [content that doesn't fit](#content-that-doesnt-fit).
- `progress` - Show (`true`, `top`, `bottom`) or hide (`false`) the [progress bar](/slides/layouts/header-footer/#progress-bar) on the slide.

The [front matter reference](/slides/front-matter/) lists every property with its values and default, including the properties of the video and animated SVG layouts. In the editor, Demo Time suggests the properties and their values while you type, and shows their description when you hover over them.

### Themes

Personalization matters! Demo Time allows you to customize the look and feel of your slides by selecting a built-in theme or creating your own.

To change your slide theme, you can specify a different theme in the slide configuration with the `theme` property or provide a custom CSS file in the demo JSON file.

<Aside>
The [themes section](/slides/themes/) of the documentation lists the built-in themes and explains how to create your own.
</Aside>

### Layouts

Demo Time supports various slide layouts, with the `layout` property, to help structure your presentation effectively:

- `default` - A standard slide layout
- `intro` - Ideal for opening slides
- `quote` - Perfect for displaying key takeaways or citations
- ... (more layouts available)

<Aside>
More information on using layouts can be found in the [layouts section](/slides/layouts/) of the documentation.
</Aside>

### Transitions

Transitions add a dynamic touch to your slides. You can specify the transition effect for your slides using the `transition` property. Demo Time supports various transitions, including:

- `fadeIn`
- `slideRight`
- `slideLeft`
- `slideUp`
- `slideDown`
- `zoomIn`
- `zoomOut`
- `rotateIn`
- `rotateOut`

<Aside type="tip">
You can change the transition effect duration by setting the `--demotime-transition-duration` CSS variable in your custom CSS file.
</Aside>

## Slide background and classes

To change the look of one slide, you don't need a custom layout or a theme of its own. Use the `background` and `class` front matter properties.

`background` sets the background of the slide. It can be:

- a CSS colour, like `"#1e3a8a"`, `navy` or `rgb(30 58 138)`;
- a CSS gradient, like `linear-gradient(135deg, #1e3a8a, #9333ea)`;
- the path (relative to the workspace folder) or URL of an image, like `.demo/assets/bg.png`. The image covers the slide.

```md
---
layout: section
background: "linear-gradient(135deg, #1e3a8a, #9333ea)"
---

# Part 2: the demo
```

<Aside type="caution">
Put a value with a `#` in it between quotes, like `background: "#1e3a8a"`. Without quotes, YAML reads everything from the `#` on as a comment.
</Aside>

A value is used as an image when it starts with `http://`, `https://`, `/`, `./` or `../`, or ends with an image extension like `.png`, `.jpg`, `.svg` or `.webp`. Any other value is used as the CSS `background`, so a `url()` in it is not resolved against the workspace folder.

When a slide sets both, the `image` property takes precedence on layouts that show it as the background. On the `image-left` and `image-right` layouts, the `image` is shown next to the content, and the `background` is the background of the whole slide.

`class` adds one or more CSS classes, separated by spaces, to the `.slide__layout` element of the slide, next to the layout and transition classes. Style them in a [custom theme](/slides/themes/custom/#style-a-single-slide):

```md
---
class: section-break dark
---

# Questions?
```

The `background` property of a slide, also one it gets from the document front matter, takes precedence over a background that a class sets in your theme. Add `!important` to the background of the class to use it on those slides.

Both properties also apply in the [slide thumbnails](#slide-thumbnails), the **Go to slide** overview, the [PDF export](/slides/export/) and the next slide preview of the [presenter view](/features/presenter-view/). In the document front matter, they apply to every slide in the file that doesn't set its own value, so you can give a whole deck the same background.

## Slide preview

When you create a slide, you can preview it by running the `Demo Time: Open slide preview` command or by clicking on the open preview (eye) action from the editor title bar.

<Image class="mx-auto" src={slidePreviewImg} alt="Slide preview action" width="400" />

### Sync the preview with the editor

While you write your slides, the slide preview follows the cursor in the markdown editor:

- **Editor to preview**: when the preview shows the file of the active editor, moving the cursor to another slide shows that slide in the preview. `Demo Time: Open slide preview` opens the preview at the slide under the cursor. Typing in a slide doesn't move the preview away from a slide you navigated to; clicking in the editor does.
- **Preview to editor**: double-click the slide, right-click it and select **Show slide contents**, or select **Reveal slide source** in the **More actions** (`…`) menu of the [slide controls](#slide-controls), to move the cursor to the source of the slide. When the file isn't open in a visible editor, it opens next to the preview.

<Aside type="tip">
Move the slide preview to an editor group next to your markdown file, so you see both while you write.
</Aside>

The sync never applies in [presentation mode](/presentation-mode/), so moving the cursor can't change slides during a talk. To turn it off, set `demoTime.slidePreviewSync` to `false`. **Reveal slide source** keeps working when the sync is off.

### Slide thumbnails

When you are not presenting and the file has more than one slide, the slide preview shows the slides of the file as numbered thumbnails in a pane on the left, in the order of the file. The current slide is highlighted.

- **Open a slide**: Click a thumbnail. When the pane has the focus, use `Up` and `Down` to go to the previous or next slide, and `Home` and `End` to go to the first or last slide. Hidden slides are not skipped.
- **Change the order**: Drag a thumbnail to another position, or press `Alt+Up` or `Alt+Down` to move the current slide. A line shows where the slide lands. Demo Time updates the markdown file, saves it and shows the moved slide. Save the file first when it has unsaved changes. Use **Undo** in the editor of the file to revert a move.
- **Hidden slides** are dimmed and have an eye icon. Slides with [content that doesn't fit](#content-that-doesnt-fit) get a warning icon.
- **Slide actions**: Right-click a thumbnail to select that slide and open the same menu as the [slide context menu](#slide-context-menu).

The thumbnails are never shown in [presentation mode](/presentation-mode/). Show or hide them with the **Toggle slide thumbnails** button in the [slide controls](#view-tools), or with the `demoTime.slidePreviewThumbnails` setting.

Moving a slide changes the front matter at the top of the file when the first slide is involved:

- When you move the first slide away, the properties that apply to every slide, like `theme`, `transition` and `class`, stay at the top of the file. The properties that only apply to the first slide, `layout`, `customLayout`, `image`, `autoAdvanceAfter` and `hide`, move with the slide.
- When you move a slide to the first position, its front matter moves to the top of the file, where `transition`, `class`, `background` and similar properties apply to every slide. Demo Time shows an error and doesn't move the slide when that would change the other slides.

<Aside type="caution">
An `openSlide` move with `slide: N` keeps its number when you change the order of the slides. Check these moves after you reorder a file.
</Aside>

### Slide context menu

Outside [presentation mode](/presentation-mode/), right-click the slide in the preview, or a thumbnail in the [slide thumbnails](#slide-thumbnails), to change it without leaving the preview. The actions update the markdown file of the slide and save it, so the preview updates right away. Use **Undo** in the editor of the file to revert a change.

- **Show slide contents**: Opens the markdown of the slide in the editor, with the cursor on the slide. See [sync the preview with the editor](#sync-the-preview-with-the-editor).
- **Edit speaker notes**: Opens the editor for the notes of the slide, and saves them in its `<!-- notes -->` block. See [notes in your slides](/features/using-notes/#notes-in-your-slides).
- **Change layout**: Sets the `layout` in the front matter of the slide to one of the [built-in layouts](/slides/layouts/). The submenu leaves out the layout the slide already uses.
- **Hide slide while presenting** / **Show slide while presenting**: Adds or removes `hide: true` in the front matter of the slide. See [hiding slides](#hiding-slides).
- **Insert slide after**: Asks for a title, and adds a slide with that heading after the slide. The preview shows the new slide and the editor opens on it, so you can write its content.
- **Duplicate slide**: Adds a copy of the slide, with its front matter and speaker notes, after it. The preview shows the copy.
- **Move slide up** / **Move slide down**: Moves the slide one position up or down in the file. See [slide thumbnails](#slide-thumbnails).
- **Delete slide**: Removes the slide from the file, after you confirm it. When you delete the first slide of a file, the front matter at the top of the file stays, without the properties that only apply to the first slide, like `layout`.

When an action can't change the slide without changing the other slides of the file, for instance when deleting the first slide would give the next slide other front matter, or when moving a slide to the first position would apply its `transition` to every slide, Demo Time shows an error and doesn't change the file. Make the change in the editor instead.

## Presenting slides

To incorporate slides into your workflow, add them as moves in your scene script or configuration files. This ensures you can control when and where your slides appear during the presentation.

Use the `openSlide` action to open a slide in the slide view.

<Tabs syncKey="open-slide">
<TabItem label="JSON">

```json
{
  "action": "openSlide",
  "path": "<relative path to the file>",
  "slide": "<slide index you want to open (1-based) (optional)>"
}
```

</TabItem>
<TabItem label="YAML">

```yaml
action: openSlide
path: <relative path to the file>
slide: <slide index you want to open (1-based) (optional)>
```

</TabItem>
</Tabs>

With this approach, you can seamlessly integrate slides into your demos, making your presentations more engaging and dynamic.

## Slide controls

When previewing or presenting slides, a compact control bar appears at the bottom of the slide. It is organized into three sections — **view tools**, **slide navigation**, and **slide tools** — and tucks the less-common actions into a **More actions** (`…`) menu so the bar stays uncluttered and adapts to narrow windows.

The control bar shows when you move the mouse over the slide. After 5 seconds without moving the mouse, the control bar and the mouse cursor hide. They stay visible while the mouse is on the control bar, also after you click **Next** or **Previous**, and while a menu or the slide overview is open.

<Image class="mx-auto" src={slideControlsImg} alt="Slide controls" />

<Aside type="note">
The control bar is keyboard and screen reader friendly. Every button is reachable with `Tab` and exposes a descriptive label, toggle buttons announce their on/off state, and the **More actions** menu opens with `Enter`/`Space` (or the arrow keys) and is navigated with the arrow, `Home`, `End`, and `Escape` keys.
</Aside>

### View tools

- **Toggle presentation mode**: Toggles presentation mode, which allows you to use your clicker or keyboard to navigate through your slides. The button is highlighted while presentation mode is active.
- **Toggle presentation view**: Toggles the presentation view, which hides VS Code UI areas (status bar, tabs, activity bar, …) for a distraction-free experience. You can also use the `setPresentationView` and `unsetPresentationView` actions, or the `Demo Time: Toggle presentation view (hides status bar, tabs, and activity bar)` command.
- **Toggle fullscreen**: Toggles Visual Studio Code's fullscreen mode.
- **Toggle slide thumbnails**: Shows or hides the [slide thumbnails](#slide-thumbnails) next to the slide preview. It saves the choice in the `demoTime.slidePreviewThumbnails` setting. The button is not shown in presentation mode.

### Slide navigation

- **Previous**: Triggers the previous move (only if the `demo-time.previousEnabled` setting is enabled or when using grouped slides).
- **Slide counter**: Shows the current slide and total (for example `01 / 05`). When slide thumbnails are available, selecting it opens the **Go to slide** overview so you can jump straight to any slide. [Hidden slides](#hiding-slides) are dimmed in the overview, but you can still open them. Slides with [content that doesn't fit](#content-that-doesnt-fit) get a warning icon.
- **Next**: Triggers the next move.

### Slide tools

- **Toggle laser pointer**: Toggles the laser pointer to highlight specific areas on your slides. The button is highlighted while the laser pointer is active.
- **Toggle zoom**: Toggles the zoom feature to zoom in on parts of your slides. The button is highlighted while zoom is active. Press `Escape` to leave zoom; this does not turn off presentation view.
- **More actions** (`…`): Opens a menu with the remaining actions, grouped for discoverability:
  - **Slide** _(only available when you are not in presentation mode)_
    - **Mouse position**: Toggles the mouse position overlay on the slide, which can be useful to position elements on your slides.
    - **Reveal slide source**: Opens the source file of the slide in the editor, with the cursor on the current slide, so you can edit it directly. You can also double-click the slide, or right-click it and select **Show slide contents**. See [sync the preview with the editor](#sync-the-preview-with-the-editor).
    - **Hide slide while presenting** / **Show slide while presenting**: Adds or removes `hide: true` in the front matter of the current slide. See [hiding slides](#hiding-slides).
    - **Add speaker notes** / **Edit speaker notes**: Opens an editor for the notes of the current slide, and saves them in its `<!-- notes -->` block. See [notes in your slides](/features/using-notes/#notes-in-your-slides).
  - **Workspace**
    - **Show demos**: Opens the Demo Time panel to access your demos and slides.
    - **Close sidebar**: Closes the side bar to provide more space for your slides.
  - **Hide controls**: Hides the slide controls and mouse, allowing you to focus on your presentation without distractions.

## Auto-advancing to the next slide

You can enable auto-advancing to the next slide after a specified duration by using the `autoAdvanceAfter` property in your slide configuration.

```markdown
---
layout: default
autoAdvanceAfter: 3
---

# Going to the next slide in 3 seconds

---
---

# End of the demo
```

When the slide has [click steps](/slides/animations/#click-steps), each interval reveals one step, and the slide moves on after the last step.

## Hiding slides

Add `hide: true` to the front matter of a slide to keep it in the file without presenting it. This is useful for backup slides for questions, an alternative ending, a slide for the long version of your talk, or a draft.

```markdown
# Thank you!

---
hide: true
---

# Backup: how the cache works
```

While [presentation mode](/presentation-mode/) is on, a hidden slide is:

- skipped when you go to the next or previous slide, including auto-advancing with `autoAdvanceAfter`;
- skipped by the next slide preview in the [presenter view](/features/presenter-view/);
- not counted by the `{{crntSlideIdx}}` and `{{totalSlides}}` [header and footer placeholders](/slides/layouts/header-footer/#placeholders) and the [progress bar](/slides/layouts/header-footer/#progress-bar).

When an `openSlide` move opens a hidden slide, the slide view continues with the next visible slide.

Hidden slides are also dimmed in the [slide thumbnails](#slide-thumbnails). They are still in the **Go to slide** overview of the [slide controls](#slide-controls), dimmed and with an eye icon. Open one from there to show it during your talk, for instance to answer a question.

Outside presentation mode, the slide preview still shows hidden slides so you can navigate to them and edit them. A hidden slide gets a dashed frame, and a **Hidden slide** bar above it.

To hide or show the current slide from the slide preview, right-click the slide, or open the **More actions** (`…`) menu of the [slide controls](#slide-controls), and select **Hide slide while presenting** or **Show slide while presenting**. This adds or removes `hide: true` in the front matter of the slide and saves the file.

<Image class="mx-auto" src={hiddenSlideImg} alt="A hidden slide in the slide preview, with the Hidden slide bar above it and the Show slide while presenting action in the More actions menu" />

<Aside type="tip">
Hidden slides are left out of the [PDF export](/slides/export/) unless you enable the `demoTime.pdfExport.includeHiddenSlides` setting.
</Aside>

## Content that doesn't fit

A slide is 960×540 pixels. When a slide has too much content, like a long code block or one bullet too many, the part that doesn't fit is cut off. How much fits depends on the theme and the fonts, so Demo Time measures the rendered slides in the slide preview and warns you:

- The slide preview shows a **Content doesn't fit the slide** badge on a slide that doesn't fit, with how much it is too tall or too wide, like **84px too tall**. A frame marks the edges of the slide, so you can see where it ends when the slide has the same background as the preview, and a striped band with a label like **↓ 84px cut off** marks every edge where content is cut off. The badge and the marks are only shown outside [presentation mode](/presentation-mode/).
- While the preview is open, it measures every slide of the file in the background, with all its [click steps](/slides/animations/#click-steps) revealed. The slides that don't fit get a warning in the **Problems** panel, on the first line of the slide, and a warning icon in the [slide thumbnails](#slide-thumbnails) and the **Go to slide** overview of the [slide controls](#slide-controls). The warnings update when you save the file.

Content counts as overflowing when it reaches past the edges of the slide. Elements with `position: absolute` or `position: fixed`, like decorations in a [custom layout](/slides/layouts/custom/), are left out, and content inside an element that scrolls or clips its content counts up to the edges of that element.

The best fix is to remove content or to split the slide in two. When that isn't an option, add `autoFit: true` to the front matter of the slide:

```markdown
---
autoFit: true
---

# The full configuration

...
```

With `autoFit`, the content of a slide that doesn't fit is scaled down until it fits, keeping the padding of the layout, to at most 50% of its size. The text wraps at the smaller size, so a long line can take less room. Slides that fit keep their size. Outside presentation mode, a **Scaled to 85% by autoFit** badge shows how much the content of the current slide was scaled down. When the content doesn't fit at 50% either, you still get the warning, which tells you that `autoFit` is on and how much is left.

`autoFit` also applies in presentation mode, the [slide thumbnails](#slide-thumbnails), the **Go to slide** overview, the [PDF export](/slides/export/) and the next slide preview of the [presenter view](/features/presenter-view/). In the document front matter, it applies to every slide in the file that doesn't set its own value.

<Aside type="tip">
The quick fix of the warning (`Ctrl+.` or `Cmd+.` on the line in the editor, or the light bulb in the **Problems** panel) adds `autoFit: true` to the front matter of the slide.
</Aside>

## Problems in slide files

Demo Time checks the front matter and code blocks of your slide files while you edit them, and reports the problems in the **Problems** panel. It checks the markdown files in the `.demo` folder, and the files that an `openSlide` move opens.

| Problem | Example | Severity |
| --- | --- | --- |
| Invalid YAML in a front matter block, at the line of the error. The slide shows these lines as content. | `theme: frost: dark` | Error |
| A misspelled property, with a **did you mean** suggestion | `transtion: fadeIn` | Warning |
| A property that Demo Time doesn't use, and that no custom layout, header or footer template reads | `speaker: Jane` | Information |
| An invalid value for `layout`, `theme`, `transition`, `controlsPosition` or `progress`, or a value that isn't `true`/`false` or a number for a property that expects one | `layout: two-column` | Warning |
| A file that doesn't exist for `image`, `video`, `svgFile`, `customTheme` or `customLayout`, or for a `background` image. Paths are relative to the workspace folder, the same way the slide preview loads them. `http(s)` URLs are not checked. | `image: .demo/assets/missing.png` | Warning, or Error for `customLayout` |
| A custom layout, or an inline `header` or `footer` template, with invalid Handlebars | `{{#if title}}` without `{{/if}}` | Error |
| A `---` followed by a line like `Note: text` (a capitalized word and a colon), which makes the lines up to the next `---` the front matter of the slide instead of its content | `Note: remember this` | Warning |
| A [code block with a `file` option](/slides/code-blocks/#code-from-workspace-files) of which the file, lines or region don't exist | ```` ```ts file="src/missing.ts" ```` | Error |

Properties that are only meant for your own templates don't get a problem as long as a [custom layout](/slides/layouts/custom/), the `header` or `footer` of the slide, or the `demoTime.slideHeaderTemplate` and `demoTime.slideFooterTemplate` templates use them.

The problems update when you change the slide file, when you add or remove a file that the slides refer to, like an image or a layout, and when you save a file that a code block shows.

<Aside type="tip">
A misspelled property or value, and a `---` that hides slide content, have a quick fix (`Ctrl+.` or `Cmd+.` on the line in the editor, or the light bulb in the **Problems** panel). For a `---`, the quick fix adds an empty line after it, so the lines are shown on the slide.
</Aside>

## Notes

Add speaker notes to a slide with a `<!-- notes` block in the slide markdown. The block is not shown on the slide, but in the presenter view and the remote control:

```md
# Why Demo Time

<!-- notes
Mention the conference from last year.
-->
```

You can also add the notes from the **More actions** (`…`) menu of the [slide controls](#slide-controls). Check the [notes section](/features/using-notes/#notes-in-your-slides) of the documentation for all the details, and for notes on the scene level.
